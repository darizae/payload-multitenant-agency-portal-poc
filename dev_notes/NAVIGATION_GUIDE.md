# Navigation Guide for the Runnable Prototype

This prototype has two surfaces:

1. **Material UI portal** — the polished operator/customer-facing flow
2. **Payload admin** — the native admin panel generated by Payload for direct document management

## Start-up checklist

1. Run `npm install`
2. Run `npm run bootstrap`
3. Run `npm run dev`
4. Visit `http://localhost:3000/login`

## Recommended walkthrough

### 1. Log in as platform admin

Use:

- Email: `platform.admin@poc.local`
- Password: `Passw0rd!Demo`

You can now:

- Open `/dashboard/agencies`
- Create a new agency in the MUI portal
- Open `/admin` to inspect the same data directly in Payload

This demonstrates **FR-1 Create Agency** and platform-level tenancy creation.

### 2. Log in as agency admin

Use:

- Email: `alpha.admin@poc.local`
- Password: `Passw0rd!Demo`

Open the Alpha Agency detail page from `/dashboard/agencies`.

From there you can:

- Create customers under Alpha Agency
- Invite agency users
- Inspect invite tokens
- Open specific customers

This demonstrates:

- **FR-5 Create Agency User**
- **FR-10 Create Customer**
- **FR-19 Assign Agency Users to Customers** (from the customer page)
- agency-scoped visibility

### 3. Open a customer page

From the agency detail, open a seeded customer such as **Northwind Bikes**.

From the customer page you can:

- Invite customer users
- Assign agency users to the customer
- See the currently assigned agency users
- Inspect invite token status for customer users

This demonstrates:

- **FR-14 Create Customer User**
- **FR-16 Invite Customer User**
- **FR-22 View Assignments**

### 4. Log in as restricted agency user

Use:

- Email: `alpha.user@poc.local`
- Password: `Passw0rd!Demo`

This seeded user is only assigned to **Northwind Bikes**.

They should:

- See the dashboard
- See only their assigned customer
- Not see unrelated customers

This demonstrates:

- strict tenant scoping
- assignment-based visibility
- **FR-21 Assignment-Based Visibility**

### 5. Log in as customer admin

Use:

- Email: `store1.admin@poc.local`
- Password: `Passw0rd!Demo`

They should:

- See only their own customer workspace
- Be able to invite additional customer users for their own customer
- Be unable to access other customers or agency-wide management

This demonstrates:

- **FR-18 Customer User Isolation**
- customer-scoped administration

### 6. Activate an invite

Any invited user creates an `invite-tokens` document automatically.

To complete the flow:

1. Copy the token shown in the portal or Payload admin
2. Open `http://localhost:3000/activate-invite/<token>`
3. Set a password
4. Return to `/login`
5. Sign in using the invited email and new password

This demonstrates the invite-first provisioning model for both agency and customer users.

## Payload admin walkthrough

Open `http://localhost:3000/admin` and log in with `platform.admin@poc.local`.

Use the generated CRUD UI to inspect and manage:

- `agencies`
- `users`
- `customers`
- `agency-customer-assignments`
- `invite-tokens`
- `audit-logs`

This validates that the prototype is really driven by Payload collections, access rules, and hooks.

## Concrete things to verify

- Try demoting or deactivating the only active agency admin in an agency: it should fail.
- Try demoting or deactivating the only active customer admin in a customer: it should fail.
- Try logging in with an invited user before activation: it should fail.
- Try browsing a customer outside the logged-in user's tenant or assignment scope: it should not be accessible.
- Check `audit-logs` after login, user creation, customer creation, or assignment changes.
